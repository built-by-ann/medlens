# AI Architecture

AI does one thing in MedLens: read clinical note text and return structured observations (mentioned medications with their dose, route, frequency, and status as each note states them, places where notes disagree, and a short summary).

It does **not** compare against the medication list, decide conflicts, resolve disagreements, match brand to generic names, or make clinical decisions. Comparison is deterministic backend code (Decision 12).

| | AI | Deterministic code |
|---|---|---|
| Identify medications and what each note literally says | ✓ | |
| Describe disagreements between notes (without resolving them) | ✓ | |
| Normalize names and fields (case, whitespace, aliases) | | ✓ `medication_normalization.py` |
| Decide whether a mention conflicts with the medication list | | ✓ `build_discrepancy_findings` |
| Assign severity | | ✓ `SEVERITY_BY_DISCREPANCY_TYPE` |
| Map a mention to its source document | | ✓ via `source_note` |
| Resolve or dismiss findings | | A human, via `POST .../resolve` |

Despite its name, `MedicationDiscrepancy.ai_explanation` is template text generated by plain Python, not by AI.

## Layout

```text
app/ai/
    providers/
        base.py                AIProvider, AIProviderError
        gemini_provider.py     default
        openbiollm_provider.py local via Ollama
        medgemma_provider.py   local via Ollama
        text_cleanup.py        strip_code_fences, extract_json_object (local providers)
    prompts.py                 SUMMARY_PROMPT_TEMPLATE, build_summary_prompt()
    schemas.py                 Medication, ClinicalSummary
    service.py                 AISummaryService, build/get_ai_summary_service()
```

`app/ai/` knows nothing about HTTP or the database: `list[str]` in, a validated `ClinicalSummary` out. Nothing in `app/services/` imports the providers.

## Flow

`POST /patients/{id}/analyses` (see [architecture.md](architecture.md#analysis-request-flow)):

1. Create the Analysis as `pending`, validating document ownership. Commit it as `processing`.
2. Read each document's `raw_text`, sorted by id, and call `AISummaryService.summarize()`. **This is the only step that leaves the process.**
3. `persist_analysis_result` stores mentions and inconsistencies, bridges extracted medications into `MedicationMention` rows, runs reconciliation, and marks the analysis `completed`.
4. On any exception: roll back, mark the analysis `failed` with a sanitized message, and return 503.

## Providers

```python
class AIProvider(ABC):
    name: str
    model: str
    @abstractmethod
    def generate_summary(self, prompt: str) -> str: ...
```

Every failure from every provider is raised as `AIProviderError`.

- **Gemini** (`google-genai`): the key is checked lazily, so the app starts without one. Uses `response_mime_type="application/json"` but no `response_schema`; Pydantic is the single source of truth for the shape. Timeout is 30s.
- **OpenBioLLM / MedGemma**: call a local Ollama server's `/api/chat` using stdlib `urllib`, with no credentials. Both use hardcoded `GENERATION_PARAMS` (`temperature=0`, `seed=0`, `num_predict=1024`) and a 120s timeout. Neither uses Ollama's JSON mode, because the benchmark measures unassisted JSON ability. Output gets syntactic cleanup only (stripping fences and surrounding prose); malformed JSON is never repaired.
  - OpenBioLLM uses `openbiollm-llama3-instruct`, built locally from `infra/ollama/openbiollm-llama3-instruct.Modelfile`. The raw GGUF has no chat template and reformulates requests as questions.
  - MedGemma uses `hf.co/bartowski/google_medgemma-4b-it-GGUF:Q4_K_M` as-is, since its template is embedded.
  - Both originally used Hugging Face hosted inference. They moved to Ollama because the hosted endpoints were unavailable (capacity and busy errors) before any benchmark case was scored. That was an infrastructure change, not a judgment about model quality.

`build_ai_summary_service(settings)` picks the provider from `AI_PROVIDER`. `get_ai_summary_service()` is the FastAPI dependency, and tests override it. The benchmark runner constructs providers directly so it can run several in one process.

## Prompt

`app/ai/prompts.py` holds the only prompt in the codebase. `build_summary_prompt(notes)` numbers the notes (`Note 1:`, `Note 2:`, ...) and fills a static template. There are no few-shot examples, no chain-of-thought, no per-provider variants, and no per-request customization. An empty list raises `ValueError`.

The model reports `source_note` for each medication, and reconciliation maps that number back to a document using the same id-sorted order. Both sides must keep that ordering.

## Structured Output

```python
class Medication(BaseModel):          # extra="forbid"
    name: str
    dosage: str | None = None
    route: str | None = None
    frequency: str | None = None
    status: str | None = None
    notes: str | None = None
    source_note: int | None = None

class ClinicalSummary(BaseModel):     # extra="forbid"
    medications: list[Medication]
    possible_inconsistencies: list[str]
    summary: str
```

- `ClinicalSummary.model_validate_json(raw)` handles both malformed JSON and schema violations. Either failure becomes `AIProviderError("AI response failed validation")`. Only the error *count* is logged, because `ValidationError` details can echo note text.
- There are **no retries and no fallback.** A failure fails the analysis once.
- `_safe_error_message` passes `AIProviderError` messages through to the API and replaces any other exception with a generic message.
- Changing the prompt's JSON shape requires updating these models by hand (Decision 16).

## Configuration

```text
AI_PROVIDER=gemini                    # gemini | openbiollm | medgemma (validated at startup)
GEMINI_API_KEY=                       # optional; missing → 503 on use
GEMINI_MODEL=gemini-2.5-flash
OLLAMA_BASE_URL=http://localhost:11434   # Compose default: http://host.docker.internal:11434
OPENBIOLLM_MODEL=openbiollm-llama3-instruct
MEDGEMMA_MODEL=hf.co/bartowski/google_medgemma-4b-it-GGUF:Q4_K_M
```

Timeouts and generation parameters are code constants, not environment settings. Unknown environment variables are ignored.

## Local Model Setup (OpenBioLLM / MedGemma)

This is one-time setup per machine. Tests never need it.

```bash
ollama pull hf.co/bartowski/google_medgemma-4b-it-GGUF:Q4_K_M
ollama pull hf.co/aaditya/OpenBioLLM-Llama3-8B-GGUF:Q4_K_M
ollama pull llama3:8b-instruct-q4_K_M          # reference template only
ollama create openbiollm-llama3-instruct -f infra/ollama/openbiollm-llama3-instruct.Modelfile

# Sanity check: each model should answer, not ask a question back
ollama run openbiollm-llama3-instruct "Extract the medication name from: patient takes lisinopril 10mg daily."

# Use in the app (backend/.env): AI_PROVIDER=openbiollm  (or medgemma)
# Benchmark smoke test:
python -m benchmark.runner --providers openbiollm medgemma --cases BENCH-001
```

## Error Handling

| Situation | `AIProviderError` message |
|---|---|
| No Gemini key | `Gemini API key is not configured` |
| Ollama unreachable | `Could not connect to Ollama at <url>. Is the Ollama server running?` |
| Model not pulled (404) | `Ollama model '<m>' is not installed. Run: ollama pull <m>` |
| Timeout | `<Provider> request timed out after <n>s` |
| Bad output | `AI response failed validation` |

Providers log `ai_request_succeeded` or `ai_request_failed` with `duration_ms`. Gemini failures also log a server-side-only `detail` (for example `models/x is not found`) that never reaches the API response (Decision 20). Prompts, note text, and raw responses are never logged.

**Model retirement:** Google retires Gemini versions periodically; `gemini-2.0-flash` broke production this way. To fix it, set `GEMINI_MODEL` and restart the backend. No rebuild is needed.

## Testing

No test calls a real provider or needs Ollama.

| Layer | File | Fake |
|---|---|---|
| Provider | `test_gemini_provider.py`, `test_openbiollm_provider.py`, `test_medgemma_provider.py` | Monkeypatched `genai.Client` / `urlopen` |
| Service | `test_ai_service.py` | `FakeProvider`; also covers `build_ai_summary_service` selection |
| Route | `test_analyses.py` | `app.dependency_overrides`, plus one test of the real wiring with no key (expects 503) |

Also covered: `test_ai_prompts.py`, `test_medication_reconciliation_service.py`, and `test_medication_normalization.py`.

## Adding a Provider

1. Add `app/ai/providers/<name>_provider.py`, subclass `AIProvider`, and wrap every SDK exception in `AIProviderError`.
2. Add a branch in `build_ai_summary_service()` and allow the name in `Settings` validation.
3. Test at all three layers.

Nothing else changes: not the service, prompt, schema, route, or reconciliation.

## Limitations

- `possible_inconsistencies` is the model's own opinion and is not checked.
- One active provider per deployment. Selection is per deployment, not per request.
- Local-model latency depends on the hardware and isn't comparable to hosted Gemini.
- See [model-evaluation.md](model-evaluation.md) for the three-model benchmark.
